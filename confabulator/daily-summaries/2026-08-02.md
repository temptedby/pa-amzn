## The two real mechanisms

**1. The floor trap.** 3,452 SP keywords: 2,275 ENABLED, 975 PAUSED, 202 ARCHIVED. **1,840 of the
2,275 enabled keywords bid exactly $0.10**, the engine floor, while July CPC was $0.59. No
impressions, so no clicks, no orders, no ACOS signal, and every bid rule only acts on keywords that
have orders. Eighty percent of the keyword list is switched on and invisible.

**2. The report queue, which is the bigger one.** `ad-engine.ts` allowed Amazon 140 seconds per
report. Measured today, real latency is ~9 minutes: SP July completed at poll 69 (~552s), SD July
was still PENDING at ~567s, SP August never completed inside 9 minutes. The live reintroduction
preview died at 151s on exactly this. So the report step has been failing routinely. `ad_engine_log`
confirms the effect: **11 distinct keywords touched in seven weeks** out of 2,164 servable, and
12:00 UTC has never once produced an action.

## Built (branch feat/sb-sd-ad-engine-2026-07-24, 8 commits, NOT deployed)

Rules written up in `.agent/ad-engine-rules-2026-08-02.md` as the single source of truth.

- **KILL** at $4 month-to-date with 0 orders or ACOS >= **52%**, the validated break-even.
- **BID** ±10% per run at that pivot.
- **HARVEST on the first conversion** as phrase + exact into the source ad group, replacing the
  >= $4 bar that added 3 keywords in six weeks.
- **Amazon's 80-char / 10-word keyword limit enforced.** An over-long converting term is shortened
  to its longest valid leading root on a word boundary rather than dropped. Fixes a live loop where
  a 98-char, 14-word term (the Single's own title) was re-submitted every run from 08-01, 8
  attempts, never once accepted.
- **REINTRODUCTION**: floored keywords come back only if they never spent or spent at ACOS < 50%,
  gated at **10 a day and nothing else**. William declined both a total spend cap ("spend as long as
  words are making money") and a concurrent-unproven ceiling, after being shown the alternative.
- **The log records outcomes, not intentions** (new `applied` column) and writes a `run` heartbeat
  on every live run, so a run that did nothing is distinguishable from a cron that never fired.
- **Deferred report jobs** (`ads-reports.ts`): one run requests, a later run collects. No pass ever
  blocks on Amazon's queue. Verified live at **6 seconds with 0 errors** where the old path died at
  151s.
- **Safety gate**: reintroduction promotes nothing unless every history window and the MTD report
  are collected, because a missing window would make a badly-spending keyword look never-spent and
  therefore eligible.
