## Research findings (for tomorrow's build)

- **Engines are pure and ready** (38/38 tests passing from April):
  - `decide(KeywordState, cfg, now)` needs three windows: `rolling7d`, `rolling3d`, `prior3d`.
  - `decideHarvest(SearchTermStats, cfg)` needs one `rolling14d` window.
  - Schema already has `keywords`, `search_terms` (with `rolling_14d_*` columns), `hourly_snapshots`, `bid_changes`.
- **Amazon bulk-ops file format** ([Bulk operations user guide PDF](https://m.media-amazon.com/images/G/01/api/guides/Bulk_operations_user_guide.pdf), [get started with SP bulksheets](https://advertising.amazon.com/API/docs/en-us/bulksheets/2-0/get-started-with-sp-bulksheets)): a single multi-tab `.xlsx` (Sponsored Products / Brands / Display / Portfolios / SP search-term report). Columns include Product, Entity (Record Type: Campaign/Ad Group/Keyword/Ad/Product Targeting), Operation, Campaign Name, Ad Group Name, Max Bid, plus performance (Impressions, Clicks, CTR, Spend, Sales, Orders, ACOS, CPC, ROAS). Format rules: `YYYYMMDD` dates, whole-number percentages, no commas, bids to 2 decimals.
- **Key design constraint:** one bulk export aggregates a *single* date range — no daily granularity. So the full momentum (3d-vs-prior-3d) comparison can't run from one export.
  - **Proposed v1:** a **7-day export** drives the high-value single-window rules (kill-switch: $4 spend / 0 conversions → pause; dead-keyword; exploration-drop), and a **14-day export** drives the full harvest engine. These are the rules that stop wasted spend and graduate winners — the bulk of the value for a $9.49 low-margin product. Full momentum tuning is layered in later (multiple exports or the daily Reporting API once the live API lands). **Confirm this scoping with William before building.**
