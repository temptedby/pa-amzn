# 2026-08-16 — the kill rule was right, and it was reading yesterday's account

Morning review across all three sources, then the live account. Found the business recovering hard,
the ad account burning faster than at any point this year, and the reason the $4 rule has been
letting words past it. Seven keywords paused live and verified. One correction I owe on a deadline.

## The headline

**The engine gets one performance snapshot per day and makes four decisions from it.** The deferred
report is cached under a key that ends with the report's end date:

```
engine-mtd|SPONSORED_PRODUCTS|spTargeting|2026-08-01|2026-08-16|targeting|...
```

That date only changes at UTC midnight, so the 00:00, 06:00, 12:00 and 18:00 runs all resolve to the
same cached report. Today's was requested at 00:00:22Z and collected at 00:40:48Z, and every run
after that read it. Amazon's account day resets at 07:00Z, so a report requested at 00:00Z covers a
day that has not started and a previous day still settling. By the 18:00 run the data is about a day
and a half old.

The engine's own cached snapshot against what those keywords had actually spent:

```
                                    engine saw    actually
phone tether clip (BROAD)              $3.40       $11.87
smartphone safety leash clip           $0.00       $ 8.69
phone retractable tether (EXACT)       $1.68       $ 7.40
phone tether tab for iphone            $0.00       $ 5.84
phone belt string (BROAD)              $2.46       $ 4.92
phone lanyard retractable (EXACT)      $3.25       $ 4.48
retractable phone tether (PHRASE)      $0.70       $ 5.42
```

Every one under the bar in the data the engine held. `shouldKill` on production is exactly William's
rule and it never had a chance to fire.

**A second fault stacks on it.** `report-warm` runs at `:40`, after the engines at `:00`, `:15`,
`:30` and `:45`. So the 00:00Z run requests and exits with no data, which is why it logs only a
heartbeat every day, and nothing refreshes the snapshot for the rest of the day.

**The worst consequence is not the missed kills.** Three of the seven were RAISED at 18:00Z, because
on a snapshot reading $0.00 they looked like words sitting out of the auction. The engine put more
money behind words that had burned $5 to $7 that same afternoon.

Sponsored Brands is unaffected: it pulls legacy v2 day reports live with no queue, which is why its
kill fired correctly this morning. Sponsored Display shares the same one-per-day cache key.

word that spends $8.50 in a day.** It records the loss, it does not prevent it.
