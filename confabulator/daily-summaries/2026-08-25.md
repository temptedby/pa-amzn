## 3. Why the monthly reactivation never reset anything: answered

Not a dead cron. `daily-sync` stamped the inventory table at `2026-08-24T14:01:30Z` against its
`0 14 * * *` schedule, so Vercel crons on this project fire.

The route and schedule have existed since 2026-06-26. But the **lifetime route inside it, the one
that finds all 141, landed on `main` on 2026-08-14**, after both monthly firings. On 1 July and
1 August only Route A existed, and the code's own comment names it a catch-22: a paused keyword does
not spend, so it cannot accumulate the trailing-window evidence Route A demands. Route A is also a
near-mirror of the kill rule, so a word the kill paused structurally fails it.

The job fired. It had nothing it could find. **1 September is the first time the lifetime route
ever runs.** One risk for that day: yesterday's dry run took 270s and `maxDuration` is 300.

### Three bugs in my own script, found before quoting it

1. The v2 Sponsored Brands report returns an 18-digit `keywordId` and I parsed it with a bare
   `JSON.parse`, which rounds it. Both SB entities read as "not found". Same defect as

2. One access token minted at startup, and a full sweep takes over an hour, so Mexico died on
   `Invalid token`. Now refreshed per section.
3. **"Not found" was counted as a pass.** William: "could not find is violation". It is now a
   violation, because an entity we cannot resolve is not a clean entity.
