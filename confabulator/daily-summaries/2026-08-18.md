## 3. THE ENGINE ACTS ONCE A DAY, NOT FOUR TIMES

The 06:04Z run made **zero** bid decisions and harvested **zero** search terms. Nothing threw.

```
report-warm   "40 */6"   ->  00:40, 06:40, 12:40, 18:40
ad-engine     "0 */6"    ->  00:00, 06:00, 12:00, 18:00
```

report-warm's own comment says it runs "~20 minutes before" the engines. It runs **5 hours 20
minutes** before. Harmless while `DATA_STALE_HOURS` was 30, because the engine re-read the previous
midnight's report. PR #5 dropped staleness to 2 hours on 08-17 at 21:16Z, and from that moment every
run except 00Z found its report stale, re-requested it, waited the 90-second inline budget, and gave
up with nothing.

The failure is silent by construction: the bid loop iterates report rows, so an empty report yields
no decisions rather than runaway raises. Safe, and invisible for a full day.

**Shipped as PR #7** (`648d61c`): warm to `"0 */6"`, engine to `"40 */6"`. Both must share a UTC hour
block because the report cache key ends with a UTC end date, so a warm at 23:40 feeding an engine at
00:00 builds a different key. 40 minutes clears the slowest queue ever measured, 31.5 minutes.
`cron-ordering.test.ts` pins it, and was verified to FAIL against the old schedule before shipping.
