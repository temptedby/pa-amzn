## 4. A third of the overpayment has a name

```
spend    CPC    ROAS   campaign
551.75  $1.31   0.57x  1st Phone Assured   AUTO_FOR_SALES, TOP +50%, PRODUCT_PAGE +50%
426.30  $0.79   0.59x  Adverio SP Manual   MANUAL, no placement adjustment
```

Same return, **66% more per click.** `AUTO_FOR_SALES` lets Amazon raise the bid up to 100% for
top-of-search, then two +50% placement multipliers stack on top, so an $0.85 keyword bid can
legitimately cost $2.55. That is why measured CPC exceeds our own bid ceiling.

The engine has never touched this. It manages keyword bids while Amazon multiplies them at the
campaign level. Removing the multipliers is worth roughly **$218/month** on August volume.

## 7. SHIPPED: the archive stopped dying at the timeout (PR #30)

`kw_day` had not written since 08-26, `ad_day_observation` since 08-23. The job was never broken.
It waited for Amazon's report queue inside one invocation. Measured live today:

```
2026-08-01..08-31   queue 256.7s   31 polls   3,855 rows
2026-07-22..07-31   queue 703.8s   85 polls     493 rows
TOTAL 961.0s against a 300s cap
```

**A 10-day window returning 493 rows took three times longer than a 31-day window returning 3,855.**
Queue time has nothing to do with how much you ask for. That killed both obvious fixes: narrowing
the window does not help because width is not the cost, and raising the timeout does not help
because 961s is beyond even the 900s ceiling. **Waiting was the bug.**

Now it asks, stores the report id, and hangs up. A later run collects. Proven end to end:

```
pass 1  1.9s  requested both       pass 2  5.9s  collected, 4,363 rows in 9 batches
kw_day  08-26 -> 08-31   6,307 -> 7,325 rows      ad_day_observation  96 -> 127
```

The five lost days match the audit exactly: 08-27 $33.44, 08-28 $46.23, 08-29 $64.45, 08-30 $51.53.
Cron moved daily -> every 4 hours. 424 tests pass.
