## 3. THE FINDING: the bid ladder is climbing into the transition

Sponsored Products, the 5.5 hours since the redirect:

```
9 RAISES   net +$0.70        2 LOWERS   net -$0.04
impressions behind each raise:   0, 0, 0, 2, 2, 3, 3, 22
```

Over seven days: **333 raises against 294 lowers, net +$16.43 of bid.**

The reasons, verbatim from `kw_bid_history`:

```
3  "no impressions and no clicks - raising until it enters the auction"
2  "3 impressions and no clicks - raising to find the position that gets one"
2  "2 impressions and no clicks - raising to find the position that gets one"
1  "22 impressions and no clicks - raising to find the position that gets one"
```

**The redirect makes this worse, not better.** A fresh 3-Pack ad in an old ad group has to re-earn
its position, so for several days every keyword registers few impressions and no clicks. That is
precisely the branch that raises. The automation will read the transition as evidence that we are
not bidding enough.

### What PR #12 would and would not fix

PR #12 (`NO_CLICK_MIN_IMPRESSIONS = 150`, open 50 days, MERGEABLE) blocks **5 of this morning's 9
raises** -- the ones with 2, 2, 3, 3 and 22 impressions. It deliberately exempts the zero-impression
climb, on the argument that *"a bid only charges when it wins a click, so raising costs nothing."*

**That argument holds only if the resulting bid is affordable.** At +50% placement times 2.0 dynamic
bidding, an $0.85 bid is a $2.55 click. The zero-impression climb is how 742 live keywords arrived
at the ceiling. The exemption is correct in a campaign with no multipliers and wrong in the one
campaign that carries 730 of our bids.

## 8. What I got wrong today

1. **I ran `intl-daily-spend.mjs` with no arguments and it answered about August.** Line 8 defaults
   to `2026-08-20..2026-08-22`. It returned CAD 2.16 of spend across three days and I was one step
   from reporting it as October. Caught before it reached William, but only just. Same class as the
   58-day window in `business-pnl.mjs` and the one already fixed in `tacos.mjs`: **a script whose
   default window is a date, not "now", will eventually answer confidently about the wrong month.**
2. **I retried a stuck Amazon report by renaming it, twice, and got HTTP 425 both times.** The v3
   reporting API deduplicates on the report **configuration**, not on the `name` field. Changing the
   name changes nothing; adding a column is what forces a new report. Cost about 20 minutes.
3. **I nearly credited PR #12 with blocking 8 of 9 raises.** It blocks 5. The zero-impression branch
   is explicitly exempt and has its own test pinning that behaviour. Corrected before reporting, and
   the exemption turned out to be the more interesting finding (section 4).
